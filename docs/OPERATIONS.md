# Governed music-rights royalty workflow

The supported API is `/api/governed-royalties`. It ingests source-digested, versioned usage statements; applies effective-dated contract versions using integer minor units and deterministic remainder allocation; records explainable calculation lines; separates financial and rights approval; queues idempotent ledger/banking posting; reconciles provider evidence; and locks accepted results. A correction or reversal is a new linked calculation in an open accounting period and never edits a locked result.

Tenant membership is checked against the database for every request. Roles separate data ingestion, calculation, rights review, payment operation, and audit. The calculator cannot approve their calculation, approvals require distinct financial and rights reviewers, overrides require a reason/evidence plus independent rights review, and only an auditor can lock reconciled results. Events, approvals, contract versions, and backtest evidence are append-only.

Provider configuration is typed and fail-closed for ledger, banking, billing, CRM, market data, documents, and filings. Every enabled synchronization records its direction, external cursor, record count, source digest, provider-evidence digest, idempotency key, and matched/mismatch outcome. Posting creates an outbox item; the HTTP request never executes an autonomous payment. Workers must preserve the idempotency key, authenticate provider evidence, record sanitized failures, retry within policy, dead-letter exhausted work, and reconcile both ledger and bank amounts before a result can advance.

Use `scripts/bootstrap.sh`, `scripts/migrate.sh`, and `scripts/seed-development.sh` only as explicit lifecycle actions. `start.sh` does not install packages, create/start PostgreSQL, create/migrate/seed a database, invent secrets, or kill occupied ports. Review the migration, take and test a restore-capable backup, set the migration acknowledgement, then apply it in a controlled environment. Rollback is forward-only because financial evidence is append-only: restore from the tested backup or deploy a reviewed compensating migration; do not drop evidence tables in place.

The local policy suite is not financial acceptance. Provider contracts and credentials, real historical usage/contract fixtures, correction and late-arriving data, tax/withholding advice, rights/legal/accounting review, bank/ledger reconciliation, security testing, migration/restore rehearsal, operations monitoring, and production sign-off remain external launch gates.
